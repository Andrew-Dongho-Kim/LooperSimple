# Loop 상태 공통화 및 검토

## 구조

공통 모듈은 `app/src/main/java/com/pnd/android/loop/state` 패키지다. 기존 Android 앱 안의 논리 모듈로 구성했으며 별도 Gradle 프로젝트나 DB 마이그레이션은 추가하지 않았다.

| 파일 | 책임 |
| --- | --- |
| `LoopState.kt` | 저장 상태 코드, 상태 판정, 응답으로 쓸 수 있는 값, 통계 확정 기준, CSV 상태 이름 |
| `LoopResponseTransition.kt` | 예정 기록 생성 및 시작·완료·건너뜀·초기화·시간 직접 입력 시 기록 전이 |
| `LoopStatePresentation.kt` | 표시 라벨과 상태 아이콘 |

Room 엔티티인 `LoopDoneVo`에서 상태 정의를 분리했다. 홈·상세·이력·통계·알림·위젯과 테스트의 참조를 새 모듈로 변경했다. `LoopBase`와 `LoopDoneVo`의 기존 편의 API는 공통 판정 함수를 호출하는 어댑터로 남겼다.

일정 및 저장 기록을 읽는 책임은 `LoopTimeline`에 유지한다. `stateOn(date)`와 `states(from, to)`로 날짜별 상태를 해석하며 홈 이력, 상세 달력, CSV가 이를 사용한다. 실제 DB 쓰기는 기존 `LoopMutationStore`의 트랜잭션을 유지하고, 쓰기 값 생성은 공통 전이 함수를 사용한다. 알람과 위젯 갱신은 트랜잭션 이후 기존 호출자가 수행한다.

화면마다 다른 배경색·크기·레이아웃은 화면에 남겼다. 표현 차이를 없애기 위해 매개변수가 많은 범용 컴포넌트를 만들기보다, 상태의 의미와 라벨·아이콘을 공유하도록 구성했다. 다이얼의 예정·시간창 진행·종료 판정은 날짜별 응답 상태와 다른 개념이므로 기존 시간 판정을 유지한다.

## 유지한 정책

- DB 코드: 비활성 `-1`, 미응답 `0`, 완료 `1`, 건너뜀 `2`, 진행 중 `3`.
- `NOT_SCHEDULED(-2)`는 표시 전용이며 응답으로 저장할 수 없다.
- 현재 활성화 설정 `enabled`와 날짜별 응답은 별개다. 새 활성화 변경은 설정 이력으로 저장한다. 기존 `DISABLED` 행도 읽을 수 있다.
- 기록이 없는 예정일은 미응답이다. 일정 밖의 메모만으로는 실행이나 통계 분모를 만들지 않는다.
- 오늘 미응답·진행 중·미래·비활성·일정 없음은 최종 완료율에서 제외한다. 오늘 완료·건너뜀과 과거 미응답은 반영한다.
- 응답 정정은 기존 날짜 키·이력 ID와 입력/측정 시간을 보존한다. 시작 및 anytime 초기화는 시간도 갱신한다.

## 수정한 문제

1. **일정 밖 메모를 미응답으로 표시**: 홈과 상세가 `day.response.done`만 읽으면 메모를 담기 위한 가상 응답까지 미응답이 된다. 공통 날짜 해석에서 실제 실행 여부를 확인해 일정 없음/비활성을 유지했다.
2. **진행 중을 기록 없음으로 표시**: 상세 달력·오늘 상태 라벨의 기본 분기가 진행 중을 누락했다. 공통 라벨을 적용했고 전체 이력 표에도 진행 중 아이콘을 추가했다.
3. **건너뜀 뒤 완료 정정 시 측정 시간 유실**: 진행 중 상태에서 건너뛰면 종료 시각이 저장되지 않았다. 완료 또는 건너뜀으로 응답할 때 실행 중인 타이머를 종료하여 이후 완료 정정에서도 실제 소요 시간을 유지한다. 자정 넘김과 정정 시각이 늦은 경우를 검증한다.
4. **시작 요청 날짜 누락**: `LoopRepository.changeLoopState`가 시작 날짜를 전달하지 않아 과거 날짜를 지정해도 오늘 시작으로 처리할 수 있었다. 요청 날짜를 `mutations.start`에 전달하여 기존의 날짜 검증을 적용한다.

## 추가 개선 의견

### 현재 비활성 설정이 과거 응답까지 막는 문제

`LoopMutationStore.respondIfUnanswered`는 `saved.loop.enabled == false`이면 즉시 종료한다. 반면 홈의 이월 항목은 오늘 껐더라도 어제 실행을 남긴다. 따라서 같은 과거 실행을 홈에서 정정할 수 있어도 위젯/알림 응답은 거부될 수 있다.

개선안: 명시한 과거 날짜의 실제 실행이 존재하면 응답을 허용하고, 현재 비활성인 루프의 새 시작 및 존재하지 않는 실행은 계속 거부한다. 날짜 자동 선택에도 `liveLoop`로 만든 가상 어제 행 대신 `occurrenceOn`을 사용한다. 비활성 시점 이후의 알림 버튼을 무시할지에 대한 정책이 함께 바뀌므로 이번 공통화에서는 동작을 유지했다.

### 이틀 이상 진행 중인 anytime 실행 누락

실제 소요 시간 계산은 절대 시각으로 하루 이상을 지원하지만, `LoopMutationStore.start/stop` 및 `currentOccurrenceDate`는 오늘과 어제 행만 찾는다. 그보다 오래 진행 중인 행은 자동 정지 대상에서 누락되거나 새 시작의 중복 방지 대상에서 빠질 수 있다.

개선안: 저장된 `IN_PROGRESS` 실행을 날짜 범위와 무관하게 조회하고, 그 실행 날짜를 UI·위젯·알림·정지 요청에 함께 전달한다. 날짜 기반 예정 실행과 사용자가 계속 진행 중인 실행을 구별하는 별도 회귀 테스트가 필요하다.

## 검증

실행 명령: `gradle :app:testDebugUnitTest :app:assembleDebug -Pksp.incremental=false -Pkotlin.incremental=false --offline --console=plain`, `git diff --check`. 로컬 캐시 Gradle 8.5와 Android Studio JBR을 사용한다.

- 공통 판정: 오늘/과거/미래, 미응답/진행 중/비활성/일정 없음/알 수 없는 값.
- 홈과 상세 날짜별 상태 일치, 일정 밖/비활성 메모, 기존 비활성 행, 명시적 일정 밖 완료 우선순위.
- 진행 중 → 건너뜀 → 완료 정정, 자정 넘김 소요 시간 보존, 잘못된 상태 및 시간 입력 거부.
- 기존 전체 단위 테스트와 Debug APK 빌드로 호출부 및 Room 호환성을 확인한다.
- 실제 단말의 화면 렌더링과 알람 전달은 별도 확인 범위다.
