# 루프 변경 이력 구현 및 검증

## 확정 정책

- 요일·시간·언제든지 변경은 오늘 미시작 실행부터 적용한다. 시간제 실행은 예정 시작 시각에 도달하면 시작한 것으로 간주한다. 진행 중·완료·건너뜀 실행과 이미 시작된 시간제 실행은 당시 계획에 고정한다.
- 최종 완료율은 해당 날짜의 일정상 예정 횟수와 명시적으로 저장한 실행을 기준으로 계산한다. 오늘의 미응답, 진행 중, 미래·생성 전, 비활성 기간은 제외한다. 과거의 예정일은 저장 행이 없어도 미응답이다.
- 일정 밖에 사용자가 직접 남긴 완료·건너뜀은 분자·분모에 함께 포함한다. 일정 밖 기록을 미응답으로 되돌리면 그 실행 행을 제거한다.
- 주간 목표 변경은 다음 월요일부터 적용한다. 같은 주 여러 번 수정하면 마지막 목표가 다음 주에 적용된다.
- 과거 일별 목록은 당시 이름·색·계획을 표시하고, 현재 목록과 순위는 최신 이름·색을 표시한다.
- 이력 도입 이전의 설정은 최초 마이그레이션 시점 설정을 고정한 추정이다. 기존 실행 시각·상태·메모를 보존하며 이후 편집으로 추정 기준이 바뀌지 않는다.
- 삭제 시 자식 데이터도 삭제한다. 상세 화면의 삭제 실행 취소는 동일한 루프 ID·이력 ID·실행·메모를 트랜잭션으로 복원한다.

## 부수 효과 방지

- 이름만 바꿔도 오늘 완료 기록이 덮이던 저장 경로를 제거했다. 설정과 실행 상태는 별도 명령으로 저장한다.
- 활성화 토글은 DB의 최신 설정에서 enabled만 변경한다. 홈 편집기도 실행에 고정된 과거 계획 대신 최신 설정을 읽는다.
- 알람 취소는 DB에 비활성 설정을 쓰지 않는다. 삭제와 비동기 저장의 경합으로 루프가 되살아나는 경로를 없앴다.
- 알림·위젯의 완료·건너뜀은 트랜잭션 안에서 아직 미응답인지 확인한다. 중복·삭제 후 요청과 과거 날짜의 시작 요청을 무시한다.
- 알람 수신 시 전달받은 오래된 설정 대신 저장된 계획을 조회한다. 전날 자정을 넘기는 종료와 오늘의 새 일정을 구분하며 종료 알람에 실행 날짜를 포함한다.
- 주간 스트립과 스트릭은 과거 요일·비활성 기간을 따른다. 진행 중인 실행으로 최종 스트릭을 끊지 않는다.
- 완료율에서 제외된 오늘 미응답은 화면의 상태 목록에 남긴다. 모든 예정 실행을 마친 날만 ‘완벽한 날’로 계산한다.
- 예정 시각, 직접 입력한 시각, 측정한 시각, 출처가 불명인 기존 기록을 구분한다. 계획 대비 실제 분석은 확실한 시간만 사용한다. 새 시작·종료 측정은 절대 시각도 보존해 자정 넘김 시간 계산을 지원한다.
- 메모와 실행에는 일자 키를 보존하고 새 쓰기는 기존 행의 기본 키를 재사용한다. 일정이 없는 날의 메모는 분모를 만들지 않는다.
- CSV는 기존 날짜·상태·메모 열 뒤에 당시 이름·색·계획·유형·추정 여부·이력 ID·목표를 추가한다.

## 검증 방법

Kotlin 테스트는 일정 변경, 같은 날 다중 변경, 실행 고정, 다음 주 목표, 비활성 구간, 추정 기준 고정, 오늘/진행 중 제외, 생성일·일정 외 실행, 시간대 변경, 자정 넘김·실제 시간, 화면 간 분모 일치 및 기존 화면 규칙을 검증한다.

`tools/verify_loop_history_migration.py`는 Room이 생성한 실제 9 → 10 SQL과 운영 코드의 초기 이력 SQL을 읽어 메모리 SQLite에서 실행한다. 원본 기록·메모, 날짜 변환, 기본 스키마, 외래키 무결성 및 삭제 후 동일 ID 복원을 검증한다. 사용자 DB를 읽거나 변경하지 않는다.

실행 명령:

```text
gradle :app:testDebugUnitTest :app:assembleDebug -Pksp.incremental=false -Pkotlin.incremental=false --offline --console=plain
python tools/verify_loop_history_migration.py
git diff --check
```

이 작업 환경은 `gradle-wrapper.jar`가 없어 캐시된 동일 버전 Gradle 8.5와 Android Studio JBR로 실행한다. KSP 증분 캐시 오류와 최종 수정분의 이전 컴파일 산출물 혼용을 피하기 위해 실행 옵션으로 KSP·Kotlin 증분 처리를 끈다. 프로젝트 의존성 버전은 변경하지 않는다.

## 검증 범위의 한계

- 이력 도입 전에 저장되지 않은 실제 설정 변경 시점은 복원할 수 없다. 해당 구간은 사용자에게 추정임을 표시한다.
- 단위 테스트 및 SQLite 마이그레이션 검증은 실제 단말의 알람 전달·Doze·화면 렌더링 검증을 대체하지 않는다. 연결된 사용자의 앱 설치·데이터 교체는 수행하지 않았다.

## 최종 검증 결과

- Kotlin 단위 테스트: 110개 통과, 실패·오류·건너뜀 0개(새 이력 회귀 테스트 34개 포함).
- 실제 생성 SQL 기반 SQLite 마이그레이션 검증: 4개 통과.
- `:app:assembleDebug`: R8 코드 축소 및 APK 패키징 성공.
- `git diff --check`: 통과.
- 검증 중 추가된 별도 다이얼·설정 화면 변경은 보존했다.
